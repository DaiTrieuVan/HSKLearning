## 1. Bối cảnh

Học sinh tự đăng ký tài khoản bằng họ tên, email và mật khẩu. Đây là endpoint **công khai**
(chưa cần đăng nhập). Mọi tài khoản đăng ký qua endpoint này đều nhận vai trò `STUDENT`.

Story này **chưa** bao gồm đăng nhập. `HTT-01-CN-004` sẽ thêm `POST /api/v1/auth/login` và JWT.
Sau khi đăng ký thành công, frontend chuyển người dùng về màn hình đăng nhập (không tự đăng nhập).

| | |
|---|---|
| Base URL dev | `http://localhost:8080` |
| Swagger UI | `http://localhost:8080/swagger-ui.html` |
| OpenAPI JSON | `http://localhost:8080/v3/api-docs` |
| OpenAPI YAML | `http://localhost:8080/v3/api-docs.yaml` |
| **Snapshot đóng băng** | [`openapi/HTT-01-CN-001.yaml`](openapi/HTT-01-CN-001.yaml) — dùng bản này để generate client, nó không đổi khi các story sau thêm route mới |
| CORS | Cho phép `http://localhost:5173` (Vite mặc định), có `credentials` |

> CORS đang bật với `allowCredentials=true`, nên frontend gọi bằng `fetch` mặc định là chạy,
> không cần header thủ công ngoài `Content-Type`.

## 2. Endpoint

```
POST /api/v1/auth/register
Content-Type: application/json
```

### Request body

| Trường | Kiểu | Bắt buộc | Ràng buộc |
|---|---|---|---|
| `fullName` | string | có | không trống, tối đa 100 ký tự |
| `email` | string | có | đúng định dạng `something@domain.tld`, tối đa 190 ký tự |
| `password` | string | có | **8–72 ký tự** (QTN-17) |
| `confirmPassword` | string | có | phải khớp `password` |

```json
{
  "fullName": "Nguyễn Văn An",
  "email": "an.hs@example.com",
  "password": "Hoctot2026",
  "confirmPassword": "Hoctot2026"
}
```

**Về `password` tối đa 72 ký tự:** BCrypt chỉ đọc 72 byte đầu tiên. Mật khẩu dài hơn sẽ bị cắt
âm thầm, nghĩa là hai mật khẩu khác nhau cùng mở được một tài khoản. Backend chặn ngay từ đầu vào
để tránh bẫy bảo mật đó. Frontend nên đặt cùng giới hạn 72 trên form.

### Hành vi với email

- Email được **trim và chuyển thành chữ thường** trước khi lưu và trước khi kiểm tra trùng.
  `NAM.HS@EXAMPLE.COM` và `nam.hs@example.com` là **một**.
- Vì vậy frontend nên hiển thị email đã chuẩn hóa từ response, không hiển thị nguyên văn người dùng gõ.

## 3. Response thành công — `201 Created`

```json
{
  "id": 1,
  "email": "an.hs@example.com",
  "fullName": "Nguyễn Văn An",
  "status": "ACTIVE",
  "roles": ["STUDENT"],
  "createdAt": "2026-10-13T03:21:44.512Z"
}
```

| Trường | Kiểu | Ghi chú |
|---|---|---|
| `id` | number | định danh tài khoản |
| `email` | string | đã chuẩn hóa chữ thường |
| `fullName` | string | đã trim khoảng trắng đầu/cuối |
| `status` | enum string | `PENDING` \| `ACTIVE` \| `LOCKED`. Đăng ký học sinh luôn ra `ACTIVE` |
| `roles` | array\<enum string> | `ADMIN` \| `TEACHER` \| `STUDENT`. Story này luôn là `["STUDENT"]` |
| `createdAt` | string (ISO-8601, UTC) | thời điểm tạo |

**Không có `Location` header.** Endpoint xem chi tiết tài khoản (`/api/v1/me`) thuộc
`HTT-01-CN-006`, nên backend không quảng bá một đường dẫn chưa tồn tại.

**Không bao giờ trả về mật khẩu**, dù dạng thuần hay dạng hash.

Dùng `roles` để quyết định mở workspace nào sau khi đăng nhập; `status` chỉ để hiển thị,
**không dùng `status`/`roles` từ client làm điều kiện phân quyền** — mọi kiểm tra quyền do server thực hiện.

## 4. Response lỗi

Mọi lỗi dùng chung một envelope:

```json
{
  "code": "EMAIL_ALREADY_IN_USE",
  "message": "Email đã được sử dụng cho một tài khoản khác",
  "path": "/api/v1/auth/register",
  "timestamp": "2026-10-13T03:21:44.512Z",
  "fields": { "email": "Email đã được sử dụng cho một tài khoản khác" }
}
```

- `code` — **mã ổn định, bất biến**, dùng để map logic. Đừng bao giờ so sánh chuỗi `message`.
- `message` — tiếng Việt, hiển thị trực tiếp được ngay.
- `fields` — **chỉ xuất hiện khi lỗi gắn với trường cụ thể**; key là tên trường trong request body.
  Khi không có lỗi trường thì toàn bộ key `fields` được **lược bỏ** (không phải `null`).
- `timestamp` — UTC, ISO-8601.

### Bảng mã lỗi của endpoint này

| HTTP | `code` | Khi nào | `fields` |
|---|---|---|---|
| `400` | `VALIDATION_FAILED` | Thiếu họ tên / email / mật khẩu / mật khẩu xác nhận; mật khẩu < 8 hoặc > 72 ký tự; email sai định dạng; họ tên > 100 ký tự | có, theo từng trường |
| `400` | `PASSWORD_CONFIRMATION_MISMATCH` | `confirmPassword` khác `password` | `confirmPassword` |
| `400` | `MALFORMED_REQUEST_BODY` | Body rỗng, không phải JSON, hoặc sai cấu trúc | không |
| `409` | `EMAIL_ALREADY_IN_USE` | Email đã tồn tại (kể cả khác nhau ở chữ hoa/thường) | không |
| `500` | `INTERNAL_ERROR` | Lỗi hệ thống ngoài ý muốn | không |

`VALIDATION_FAILED` có thể chứa **nhiều trường cùng lúc**. Ví dụ bỏ trống cả mật khẩu và mật khẩu
xác nhận:

```json
{
  "code": "VALIDATION_FAILED",
  "message": "Dữ liệu nhập không hợp lệ",
  "path": "/api/v1/auth/register",
  "timestamp": "2026-10-13T03:21:44.512Z",
  "fields": {
    "password": "Mật khẩu không được để trống",
    "confirmPassword": "Mật khẩu xác nhận không được để trống"
  }
}
```

### Text cụ thể của từng lỗi validation

Những chuỗi này backend đang trả về — frontend nên ưu tiên render từ `fields`, chỉ hardcode
khi cần. Chúng được liệt kê để team FE viết test khớp.

| Điều kiện | `fields` key | `message` |
|---|---|---|
| họ tên trống | `fullName` | `Họ tên không được để trống` |
| họ tên > 100 ký tự | `fullName` | `Họ tên tối đa 100 ký tự` |
| email trống | `email` | `Email không được để trống` |
| email > 190 ký tự | `email` | `Email tối đa 190 ký tự` |
| email sai định dạng | `email` | `Email không đúng định dạng` |
| mật khẩu trống | `password` | `Mật khẩu không được để trống` |
| mật khẩu 7 ký tự trở xuống | `password` | `Mật khẩu phải có tối thiểu 8 ký tự (tối đa 72 ký tự)` |
| mật khẩu trên 72 ký tự | `password` | `Mật khẩu phải có tối thiểu 8 ký tự (tối đa 72 ký tự)` |
| mật khẩu xác nhận trống | `confirmPassword` | `Mật khẩu xác nhận không được để trống` |
| mật khẩu xác nhận lệch | `confirmPassword` | `Mật khẩu xác nhận không khớp` |
| email đã dùng | *(không có `fields`)* | `Email đã được sử dụng cho một tài khoản khác` (ở cấp `message`) |

> **Lưu ý cho AC `HTT-01-CN-001-TC-05`** ("giữ lại các trường đã nhập"): backend **không** trả về
> dữ liệu đã nhập trong response lỗi. Đó là hành vi phía form — khi nhận `400`, giữ nguyên giá trị
> các input và chỉ gắn thông báo vào các trường có trong `fields`.

## 5. Mapping đề xuất cho form đăng ký

```ts
type ApiError = {
  code: string;
  message: string;
  path: string;
  timestamp: string;
  fields?: Record<string, string>;
};

function applyRegisterError(error: ApiError, form: FormApi) {
  if (error.code === "EMAIL_ALREADY_IN_USE") {
    // Lỗi cấp tài nguyên, không gắn với một input cụ thể nào -> banner trên đầu form.
    form.setBanner(error.message);
    return;
  }
  if (error.fields) {
    for (const [name, message] of Object.entries(error.fields)) {
      form.setFieldError(name, message); // giữ nguyên giá trị người dùng đã gõ
    }
    return;
  }
  form.setBanner(error.message); // MALFORMED_REQUEST_BODY / INTERNAL_ERROR
}
```

Quy tắc chung cho **toàn bộ API** (không chỉ story này): switch trên `code`, render `message` và
`fields` thẳng ra UI. Không parse chuỗi thông báo.

## 7. Coverage acceptance criteria

| AC | Nội dung | Được kiểm chứng bởi |
|---|---|---|
| `TC-01` | Đăng ký hợp lệ → tạo tài khoản, gán STUDENT, báo thành công | `RegisterStudentH2Test`, `RegisterStudentApiTest` |
| `TC-02` | Email đã dùng → báo lỗi, không tạo tài khoản | như trên, thêm case chữ hoa/thường |
| `TC-03` | Mật khẩu < 8 ký tự → báo rõ lý do (QTN-17) | như trên, kèm biên 8 / 7 ký tự |
| `TC-04` | Email sai định dạng → báo lỗi | như trên (`an.hs@`, `an.hs.example.com`) |
| `TC-05` | Mật khẩu xác nhận không khớp → báo lỗi | như trên |
| `TC-06` | Thiếu họ tên / email / mật khẩu → báo trường nào thiếu | như trên |
| `CV-04` | Mật khẩu băm BCrypt, cho phép đăng nhập | testpost-condition: `passwordEncoder.matches(raw, storedHash)` |

`RegisterStudentApiTest` chạy trên **MySQL thật** (kèm migration `V1`); tự skip khi chưa setup DB.
`RegisterStudentH2Test` chạy **không cần DB**, luôn xanh, và bao phủ toàn bộ hợp đồng HTTP.
Chạy: `cd backend && .\mvnw.cmd test`.
