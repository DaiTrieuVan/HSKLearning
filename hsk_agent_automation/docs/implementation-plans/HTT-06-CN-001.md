# Implementation Plan — HTT-06-CN-001: Giao bài cho lớp

## 1. Nguồn và phạm vi
- **Story:** HTT-06-CN-001 — Giao bài cho lớp (Assign Exercise to Classroom).
- **Epic:** HTT-06 — Giao bài, làm bài và chấm điểm.
- **Vai trò:** Giáo viên (Teacher / Admin).
- **Mục tiêu:** Cho phép giáo viên chọn bài tập đã soạn, chỉ định lớp học, thiết lập thời gian bắt đầu (giao ngay hoặc lên lịch trong tương lai) và hạn nộp bài. Hệ thống tạo một "Lần giao bài" (Assignment) độc lập, tự động chụp lại toàn bộ snapshot nội dung câu hỏi, đáp án, điểm số theo quy tắc cố định dữ liệu.
- **Quy tắc nghiệp vụ liên quan:**
  - `QTN-01`: Cách ly dữ liệu giữa các lớp. Giáo viên chỉ thấy và thao tác trên lớp do mình phụ trách (`teacher_id`). Từ chối truy cập nếu lớp thuộc giáo viên khác (HTTP 403 Forbidden).
  - `QTN-09`: Bài tập chỉ giao khi hợp lệ. Bài tập giao cho lớp bắt buộc phải có ít nhất 1 câu hỏi và hạn nộp (`due_time`) phải sau thời điểm bắt đầu/thời điểm giao (`start_time`).
  - `QTN-10`: Nội dung lần giao bài được cố định (Snapshot). Khi giao bài, hệ thống chụp lại toàn bộ câu hỏi, đáp án đúng, giải thích và điểm từng câu gắn liền với lần giao bài đó. Việc sửa ngân hàng câu hỏi hay bài tập gốc về sau tuyệt đối không ảnh hưởng đến lần giao bài đã tạo.
  - `QTN-19`: Quyền sở hữu nội dung. Giáo viên chỉ được giao bài tập do chính mình sở hữu hoặc quản lý.
- **Acceptance Criteria & Test Cases:**
  - `TC-01`: Luồng thành công — Giao ngay cho lớp đang hoạt động (`ACTIVE`), hạn nộp sau hiện tại -> Bài được giao thành công cho toàn bộ học sinh trong lớp, hiển thị trong danh sách bài của lớp.
  - `TC-02`: Luồng lên lịch — Đặt thời gian bắt đầu trong tương lai (`start_time > now()`) -> Bài chuyển trạng thái `SCHEDULED`, học sinh chỉ thấy và làm được từ thời điểm bắt đầu.
  - `TC-03`: Dữ liệu không hợp lệ — Hạn nộp không sau thời điểm bắt đầu/giao (`due_time <= start_time`) -> Báo lỗi HTTP 400 (`ASSIGNMENT_DUE_DATE_INVALID`), không giao bài.
  - `TC-04`: Dữ liệu rỗng — Bài tập chưa có câu hỏi nào (`0 câu`) -> Báo lỗi HTTP 400 (`ASSIGNMENT_EXERCISE_EMPTY`), chặn giao bài.
  - `TC-05`: Thiếu dữ liệu — Chưa chọn lớp hoặc chưa đặt hạn nộp -> Báo lỗi validation HTTP 400 (`ASSIGNMENT_CLASS_REQUIRED`, `ASSIGNMENT_DUE_DATE_REQUIRED`).
  - `TC-06`: Sai trạng thái — Giao bài cho lớp đã lưu trữ (`ARCHIVED`) -> Báo lỗi HTTP 400 (`CLASS_ALREADY_ARCHIVED`), từ chối giao bài.
  - `TC-07`: Không có quyền (Lớp) — Giao bài cho lớp của giáo viên khác -> Từ chối HTTP 403 Forbidden (`FORBIDDEN`).
  - `TC-08`: Không có quyền (Bài tập) — Giao bài tập của giáo viên khác -> Từ chối HTTP 403 Forbidden (`ACCESS_DENIED_EXERCISE`).
  - `TC-09`: Ngoại lệ — Học sinh mới tham gia lớp sau khi giao bài -> Vẫn thấy bài nếu bài còn trong hạn nộp (`due_time > now()`).
  - `TC-10`: Lưu lịch sử — Hệ thống ghi nhận nhật ký giao bài (Audit log) kèm thông tin giáo viên, bài tập, lớp, thời gian bắt đầu, hạn nộp và bản chụp nội dung.
  - `TC-11`: Giao nhiều lần — Một bài tập có thể giao nhiều lần (cho nhiều lớp hoặc cùng một lớp) tạo ra các lần giao độc lập với kết quả riêng.
  - `TC-12`: Cố định snapshot (QTN-10) — Sửa bài tập gốc sau khi giao -> Snapshot của lần giao đã tạo không đổi.

## 2. Phân tích hiện trạng Database & Tái sử dụng Schema (Tuân thủ Quy tắc 5 GEMINI.md)

### Rà soát schema hiện có:
- Các bảng hiện tại: `users`, `classes`, `class_members`, `exercises`, `exercise_questions`, `questions`, `question_options`.
- Hiện tại trong toàn bộ schema **CHƯA CÓ** thực thể hay bảng lưu trữ các "Lần giao bài" (Assignment).

### Giải trình sự cần thiết tạo bảng mới:
- Theo nghiệp vụ Epic HTT-06 (Giao bài, làm bài và chấm điểm), một bài tập (`exercises`) chỉ là khuôn mẫu/thư viện câu hỏi. Khi giao cho lớp, hệ thống cần một thực thể độc lập là "Lần giao bài" (`assignments`) để lưu:
  1. Mối liên kết giữa bài tập cụ thể và lớp học cụ thể.
  2. Thời gian bắt đầu làm bài và hạn chót nộp bài (`start_time`, `due_time`).
  3. Trạng thái lần giao (`SCHEDULED`, `ACTIVE`, `CLOSED`, `ARCHIVED`).
  4. Bản chụp snapshot toàn vẹn (`snapshot_data` dưới dạng JSON chuẩn hóa) gồm toàn bộ câu hỏi, đáp án, điểm số theo đúng yêu cầu QTN-10.
  5. Đóng vai trò thực thể cha để liên kết với các lượt làm bài của học sinh (`submissions`) trong các story tiếp theo (HTT-06-CN-002, CN-003,...).
- Việc tạo bảng `assignments` là hoàn toàn độc lập, cần thiết và tuân thủ chặt chẽ quy định về việc chỉ tạo bảng khi phát sinh nghiệp vụ thực thể mới.

### Migration đề xuất: `V12__create_assignment_tables.sql`
```sql
CREATE TABLE IF NOT EXISTS assignments (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    exercise_id BIGINT NOT NULL,
    class_id BIGINT NOT NULL,
    teacher_id BIGINT NOT NULL,
    title VARCHAR(255) NOT NULL,
    description TEXT NULL,
    start_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    due_time TIMESTAMP NOT NULL,
    total_points DECIMAL(6,2) NOT NULL DEFAULT 0.00,
    status VARCHAR(50) NOT NULL DEFAULT 'ACTIVE',
    snapshot_data LONGTEXT NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT fk_assignments_exercise FOREIGN KEY (exercise_id) REFERENCES exercises(id) ON DELETE RESTRICT,
    CONSTRAINT fk_assignments_class FOREIGN KEY (class_id) REFERENCES classes(id) ON DELETE CASCADE,
    CONSTRAINT fk_assignments_teacher FOREIGN KEY (teacher_id) REFERENCES users(id) ON DELETE RESTRICT,
    INDEX idx_assignments_class (class_id),
    INDEX idx_assignments_teacher (teacher_id),
    INDEX idx_assignments_due_time (due_time),
    INDEX idx_assignments_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

## 3. Kiến trúc Backend & API Contracts

### A. Data Contracts (DTOs)
1. **AssignExerciseRequest:**
   ```java
   public record AssignExerciseRequest(
       @NotNull(message = "Mã bài tập không được để trống") Long exerciseId,
       @NotNull(message = "Vui lòng chọn lớp học để giao bài") Long classId,
       Instant startTime, // Nullable, nếu null sẽ lấy Instant.now()
       @NotNull(message = "Hạn nộp bài không được để trống") Instant dueTime
   ) {}
   ```
2. **AssignmentSnapshotQuestionDto:**
   ```java
   public record AssignmentSnapshotQuestionDto(
       Long questionId,
       String type,
       String content,
       String explanation,
       String payload,
       BigDecimal points,
       Integer sortOrder,
       List<AssignmentSnapshotOptionDto> options
   ) {}
   ```
3. **AssignmentResponse:**
   ```java
   public record AssignmentResponse(
       Long id,
       Long exerciseId,
       Long classId,
       String classTitle,
       Long teacherId,
       String title,
       String description,
       Instant startTime,
       Instant dueTime,
       BigDecimal totalPoints,
       String status, // SCHEDULED, ACTIVE, CLOSED, ARCHIVED
       int questionCount,
       Instant createdAt
   ) {}
   ```
4. **AssignmentDetailResponse:** Kế thừa thông tin chung và kèm danh sách câu hỏi snapshot (cho giáo viên xem hoặc học sinh làm bài).

### B. Endpoints API
- `POST /api/assignments`:
  - Quyền: `ROLE_TEACHER`, `ROLE_ADMIN`
  - Thực hiện xác thực QTN-01 (giáo viên sở hữu lớp, lớp không bị ARCHIVED), QTN-19 (giáo viên sở hữu bài tập), QTN-09 (bài có >= 1 câu hỏi, dueTime > startTime).
  - Đóng gói snapshot JSON và lưu vào bảng `assignments`.
  - Ghi Audit Log (`ASSIGN_EXERCISE_TO_CLASS`).
  - Trả về HTTP 201 Created cùng `AssignmentResponse`.
- `GET /api/assignments/classes/{classId}`:
  - Quyền: Giáo viên quản lý lớp hoặc Học sinh đang hoạt động trong lớp (`class_members.status = ACTIVE`).
  - Nếu là Giáo viên: Trả về toàn bộ danh sách bài đã giao cho lớp.
  - Nếu là Học sinh:
    - Trả về bài đã giao nếu `due_time > now()` hoặc nếu đã qua `start_time` (hỗ trợ TC-09 học sinh mới tham gia lớp).
- `GET /api/assignments/{id}`:
  - Xem chi tiết một lần giao bài kèm nội dung snapshot.
