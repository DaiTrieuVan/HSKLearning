### 1. BỐI CẢNH & MỤC TIÊU NGHIỆP VỤ

User Story **HTT-07-CN-008** cho phép **Quản trị viên nền tảng (Platform Admin)** xem bảng tổng quan các chỉ số hoạt động toàn hệ thống (số lượng người dùng theo vai trò, số lớp học, số bài học HSK, số bài nộp bài tập), hỗ trợ lọc theo các khoảng thời gian (7 ngày qua, 30 ngày qua, Toàn thời gian) để theo dõi tốc độ phát triển và tình hình vận hành của nền tảng.

#### Các Acceptance Criteria & Test Cases:
- **TC-01 (Luồng thành công — Thống kê toàn cảnh hệ thống):**
  - Given: Quản trị viên đã đăng nhập.
  - When: Quản trị viên mở trang tổng quan thống kê.
  - Then: Hệ thống hiển thị:
    1. Số người dùng phân theo vai trò (Học sinh, Giáo viên, Quản trị viên).
    2. Số người dùng theo trạng thái (Đang hoạt động ACTIVE, Bị khóa LOCKED).
    3. Số lượng lớp học (Tổng số lớp, Đang mở ACTIVE, Đã lưu trữ ARCHIVED).
    4. Số lượng bài học HSK và số cấp độ HSK.
    5. Số lượng bài nộp bài tập (Tổng số bài nộp).
- **TC-02 (Luồng thành công — Lọc theo khoảng thời gian):**
  - Given: Quản trị viên chọn bộ lọc thời gian: `7 ngày qua` (`7D`), `30 ngày qua` (`30D`), hoặc `Toàn thời gian` (`ALL`).
  - When: Hệ thống tính toán chỉ số.
  - Then: Số lượng đối tượng mới tạo trong kỳ (Người dùng mới, Lớp mới, Bài nộp mới) khớp chuẩn xác với mốc thời gian lọc.
- **TC-03 (Dữ liệu rỗng — Hệ thống mới khởi tạo):**
  - Given: Hệ thống mới chưa có nhiều dữ liệu (hoặc các bảng rỗng).
  - When: Quản trị viên mở trang thống kê.
  - Then: Các số liệu hiển thị 0 an toàn, giao diện không bị crash hay báo lỗi.
- **TC-04 (Kiểm soát phân quyền — Chỉ ADMIN được phép):**
  - Given: Người dùng có vai trò là Giáo viên hoặc Học sinh.
  - When: Cố tình truy cập trang hoặc gọi API thống kê hệ thống.
  - Then: Hệ thống từ chối truy cập với mã lỗi `403 FORBIDDEN`.

### 2. PHÂN TÍCH HIỆN TRẠNG & THIẾT KẾ KỸ THUẬT (SENIOR BACKEND MODE)

#### A. Zero DB Migration
Tái sử dụng 100% các bảng hiện có:
- `users`, `roles`, `user_roles`
- `classes`
- `lessons`, `hsk_levels`
- `assignment_submissions`

#### B. API Contract & DTO Structures
- **Endpoint:** `GET /api/admin/system-stats?period=ALL|7D|30D`
- **Quyền hạn:** `@PreAuthorize("hasRole('ADMIN')")`
- **Response DTO:** `SystemStatisticsResponse`
```json
{
  "period": "7D",
  "totalUsers": 120,
  "studentCount": 105,
  "teacherCount": 12,
  "adminCount": 3,
  "activeUsers": 118,
  "lockedUsers": 2,
  "totalClasses": 15,
  "activeClasses": 13,
  "archivedClasses": 2,
  "totalLessons": 60,
  "totalLevels": 6,
  "totalSubmissions": 450,
  "newUsersInPeriod": 14,
  "newClassesInPeriod": 2,
  "newSubmissionsInPeriod": 85
}
```

#### C. Tối ưu hóa truy vấn Backend
- Sử dụng các câu truy vấn `count()` có sẵn chỉ mục của JPA Repository:
  - `userRepository.count()`
  - `userRepository.countByStatus(UserStatus.ACTIVE)`
  - `userRoleRepository.countByRole_Code(RoleCode.STUDENT)`
  - `classRepository.count()`, `classRepository.countByStatus(...)`
  - `assignmentSubmissionRepository.count()`
  - Với các chỉ số trong kỳ (`7D`, `30D`): sử dụng query `countByCreatedAtAfter(sinceDate)`.
