### 1. BỐI CẢNH & MỤC TIÊU NGHIỆP VỤ

User Story **HTT-08-CN-004** hiện thực hóa quy tắc nghiệp vụ **QTN-16 (Chuỗi ngày học - Streak)**. Học sinh có động lực học đều đặn mỗi ngày khi nhìn thấy chuỗi ngày học liên tiếp tăng dần.
- Chuỗi streak tăng thêm 1 khi học sinh hoàn thành mục tiêu ngày (Daily Challenge của `HTT-08-CN-003`).
- Nếu học sinh bỏ lỡ 1 ngày (không hoàn thành mục tiêu ngày trước đó), streak sẽ bị đứt và trở về 0.
- Ranh giới ngày tính chuẩn xác theo múi giờ Việt Nam `Asia/Ho_Chi_Minh` (UTC+7).

#### Acceptance Criteria & Test Cases (TC-01 đến TC-08):
- **TC-01 (Ngày đầu tiên):** Hoàn thành mục tiêu ngày đầu tiên -> Streak = 1.
- **TC-02 (Ngày kế tiếp liên tiếp):** Đã có streak 1, hoàn thành mục tiêu ngày kế tiếp -> Streak tăng lên 2.
- **TC-03 (Hiển thị trang chính):** Mở trang chính -> Hiển thị streak hiện tại (ví dụ: `5 ngày`).
- **TC-04 (Chống lặp trong ngày - Idempotent):** Hoàn thành mục tiêu lần nữa trong cùng một ngày -> Streak chỉ tăng 1 cho ngày đó.
- **TC-05 (Bỏ lỡ 1 ngày):** Bỏ lỡ một ngày không hoàn thành mục tiêu (qua hết ngày đó theo giờ Việt Nam) -> Streak đặt lại về 0.
- **TC-06 (Chưa hoàn thành hôm nay nhưng hôm qua đã xong):** Đang trong ngày hôm nay mà chưa hoàn thành mục tiêu -> Streak vẫn hiển thị giá trị hiện tại (ví dụ: 5 ngày), chỉ đặt lại về 0 khi qua hết ngày mà vẫn chưa hoàn thành.
- **TC-07 (Múi giờ Việt Nam):** Ranh giới ngày tính theo `Asia/Ho_Chi_Minh` UTC+7 (ví dụ 00:10 ngày 13/10 giờ VN = 17:10 ngày 12/10 UTC, phải tính vào ngày 13/10).
- **TC-08 (Quay lại sau nhiều ngày nghỉ):** Nghỉ nhiều ngày rồi quay lại hoàn thành mục tiêu -> Streak bắt đầu lại từ 1.

### 2. THIẾT KẾ CƠ SỞ DỮ LIỆU & KIẾN TRÚC BACKEND

#### A. Database Schema (Flyway Migration `V17__create_user_streaks_table.sql`):
```sql
CREATE TABLE IF NOT EXISTS user_streaks (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL UNIQUE REFERENCES users(id) ON DELETE CASCADE,
    current_streak INT NOT NULL DEFAULT 0,
    longest_streak INT NOT NULL DEFAULT 0,
    last_completed_date DATE,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_user_streaks_user_id ON user_streaks(user_id);
```

#### B. Thuật toán tính Streak (Senior Backend Mindset):
1. **Ranh giới thời gian:** Sử dụng `ZoneId.of("Asia/Ho_Chi_Minh")`.
2. **Khi học sinh xem Streak (`getStreakStatus`):**
   - `referenceDate`: Mặc định là ngày hôm nay theo UTC+7.
   - Nếu chưa có bản ghi hoặc `last_completed_date == null`: `currentStreak = 0, completedToday = false`.
   - Nếu `last_completed_date.equals(today)`: `completedToday = true`, streak là `current_streak`.
   - Nếu `last_completed_date.equals(today.minusDays(1))`: Học sinh đã xong hôm qua, hôm nay chưa xong. Theo **TC-06**, streak vẫn giữ nguyên `current_streak` và `completedToday = false`.
   - Nếu `last_completed_date.isBefore(today.minusDays(1))`: Bỏ lỡ ít nhất cả ngày hôm qua. Theo **TC-05**, streak bị đứt -> tính là `currentStreak = 0, completedToday = false`.
3. **Khi hoàn thành thử thách ngày (`recordStreakCompletion`):**
   - Được gọi tự động trong `DailyChallengeService` khi người dùng hoàn thành 3 mục tiêu trong ngày.
   - Nếu `last_completed_date == null`: Bắt đầu chuỗi: `current_streak = 1`.
   - Nếu `last_completed_date.equals(completedDate)`: Đã tính cho ngày này rồi (TC-04: Idempotent) -> Không tăng thêm.
   - Nếu `last_completed_date.equals(completedDate.minusDays(1))`: Ngày liên tiếp (TC-02) -> `current_streak += 1`.
   - Nếu `last_completed_date.isBefore(completedDate.minusDays(1))`: Chuỗi đã bị đứt trước đó (TC-08) -> `current_streak = 1`.
   - Luôn cập nhật `longest_streak = Math.max(longest_streak, current_streak)`.
   - Gán `last_completed_date = completedDate`.

#### C. DTO & REST API Contracts:
- `GET /api/v1/gamification/streak?date=YYYY-MM-DD`:
  ```json
  {
    "currentStreak": 3,
    "longestStreak": 7,
    "completedToday": true,
    "lastCompletedDate": "2026-10-22",
    "message": "Tuyệt vời! Bạn đang duy trì chuỗi học 3 ngày liên tiếp."
  }
  ```
